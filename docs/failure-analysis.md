# 실패 분석

증상을 기록한 것과 원인을 증명한 것은 다릅니다. 아래 결론은 남은 대화 범위에 한정합니다.

## F01 · 경계·형태·시간적 일관성 문제

**관찰:** 경계선, 영역이 떠 보이는 느낌, 움직임에 비해 형태 변화가 둔한 결과, 색·윤곽의 부자연스러움이 보고되었습니다. 보정 후 흐림은 줄었지만 경계가 강조되었다는 보고도 있습니다.

**검토한 가능성:** 분할 품질, 입력 분포와 변형 범위, 학습 설정과 진행량, 후처리 설정, 버전별 동작 차이.

**결론:** 어느 한 원인으로 설명된다고 확인하지 못했습니다. 여러 요인의 가능성을 분리할 실험이 부족했습니다. “복합 원인으로 확정”이나 “회귀 버그 확인”도 현재 근거보다 강한 표현입니다.

**다음 검증 제안:** 동일 입력·학습 상태·preset을 고정하고 한 구성 요소만 변경합니다. 현재 그 시험은 수행하지 않았습니다.

## F02 · 분할 및 가림 처리의 불일치

**관찰:** 자동 분할이 경계를 잘 처리하는 경우와 불필요한 영역까지 포함하는 경우가 있다는 보고가 있었습니다. 비슷해 보이는 조건에서도 다른 결과를 보고했습니다.

**미확인:** 같은 입력 배열과 분할 상태, 전처리 설정으로 재실행했는지. 학습 입력 선택 규칙과 분할 상태 유지 방식도 현재 코드로 검증하지 못했습니다.

**교훈:** 최종 결과만으로 분할 단계의 책임을 확정하지 않습니다. 단계별 중간 결과를 비교하는 계획이 필요합니다.

## F03 · GPU 메모리 부족

**관찰:** 여러 후처리 보정 기능을 켠 상태에서 재생 시 OOM이 발생했다고 사용자가 보고했습니다.

**미확인:** 해당 시점의 VRAM 계측, 동시 프로세스, 기능별 할당량과 전체 오류 스택. 학습 batch 비교와 별개의 사건입니다.

**다음 제안:** 같은 작업에서 보정 기능을 하나씩 추가하며 peak memory와 실패 시점을 기록합니다. 이 시험 결과는 아직 없습니다.

## F04 · GPU 런타임과 웹 UI 의존성

| 남은 증거 | 말할 수 있는 것 | 말할 수 없는 것 |
|---|---|---|
| `ModuleNotFoundError: No module named 'torch'` | 그 실행 환경에서 import 실패 | GPU나 드라이버가 원인이라는 단정 |
| GPU 실행 공급자 초기화·재시도 오류 | 런타임 세션 생성 단계 문제 보고 | 특정 DLL 하나가 유일 원인이라는 단정 |
| CUDA 공급자 목록 출력 | 해당 패키지가 공급자를 노출 | 실제 계산이 전부 GPU에서 수행됨 |
| Gradio API/schema 처리 예외 | UI의 API 정보 생성 경로에서 실패 | 특정 패키지 버전의 보편적 결함 증명 |
| 이후 기동 메시지 | 시작 절차가 더 진행된 기록 | 전체 작업 성공·장시간 안정성 |

당시 출력에는 Gradio 5.1.0 / client 1.4.0과 함께 Pydantic·FastAPI·Starlette의 서로 다른 버전 조합이 나타납니다. 한 조합에서는 schema 처리 예외가, 변경 후에는 기동 메시지가 남았습니다. 여러 의존성이 함께 바뀌었으므로 개별 버전의 인과 효과를 분리하지 않았습니다. 이는 **역사적 환경 기록**이며 현재의 설치·보안 권장안이 아닙니다.

## F05 · 실험 상태와 자료 보존

과거에는 이미 반영된 Git 변경을 다시 처리하려 하거나 백업 경로 준비가 되지 않아 오류가 발생했습니다. 현재는 과거 코드가 남아 있지 않아 분석 범위가 제한됩니다. 앞으로는 변경 전 상태 확인, 보관본 검증, 작은 커밋과 실행 결과의 연결이 필요합니다.

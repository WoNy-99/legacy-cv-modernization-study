# 성능 관찰: 벤치마크와 구분

## 하드웨어 및 메모리

사용자는 NVIDIA RTX 4070 SUPER 12 GB 환경이라고 설명했습니다. 한 학습 시작 출력에는 `VRAM: 9.20GB`라고 표시되어 있습니다. 이 표시의 정확한 의미를 현재 코드로 확인하지 못했으므로 **실제 사용량 9.20 GB**, peak memory, 또는 물리 용량으로 해석하지 않습니다.

12 GB 자원이 설정 선택의 제약이었다는 사용자 설명은 있지만, 해상도·배치별 실제 VRAM 사용량 표는 없습니다.

## 배치 8과 16의 관찰

| 항목 | batch 8 | batch 16 |
|---|---|---|
| 사용자가 설명한 반복 시간 | 약 250~380 ms | 약 431~660 ms |
| 기록 성격 | 이전 실행에 대한 요약 | 변경 이후 관찰 범위 |
| 비교 제한 | 입력 규모와 실행 시점이 다름 | 배치 외 조건도 변경됨 |

위 범위는 raw timing 전체를 집계한 평균·신뢰구간이 아닙니다. 사용자의 당시 설명을 전사한 것입니다. 후속 batch 16 학습 로그에는 400 ms대, 별도 후반 구간에는 300 ms대 표시도 있으며 구간·설정이 다릅니다.

**결론:** 배치가 커지면서 표시 반복 시간이 길어졌다는 관찰까지 가능합니다. 샘플 처리량 개선, 최적 배치, batch별 메모리 절감, 학습 시간 단축은 입증하지 못했습니다.

## 반복 시간만으로 처리량을 결론 내리지 않은 이유

샘플 처리량을 비교하려면 한 iteration의 실제 작업량과 시간 범위가 동일하게 정의되어야 합니다. 표시 시간이 전체 반복을 포함하는지, 준비·전송·추가 처리 비용을 포함하는지 현재 확인되지 않습니다. 따라서 이 수치를 단순히 `batch / time`으로 환산해 검증된 samples/sec로 발표하지 않습니다.

## CPU 교체 관찰

2026-06 대화에는 CPU 교체 후 이전 약 500~900 ms와 달리 300 ms 안팎의 반복 시간이 관찰되었다는 설명과 일부 출력이 있습니다. 동시에 이전에 없었던 시스템 문제도 보고했습니다. CPU 공급 병목이 개선되었다는 설명은 가설이며, 소프트웨어 현대화 성과나 통제된 하드웨어 벤치마크가 아닙니다.

## OOM의 위치

메모리 부족은 복수 후처리 기능 사용 중 보고되었습니다. 학습 batch 16과 직접 연결하지 않습니다. 정량 VRAM 추적이나 OOM 임계값 측정은 없습니다.

## 새 측정 템플릿의 범위

[benchmark_template.py](../scripts/benchmark_template.py)는 이번에 새로 작성한 표준 라이브러리 기반 예시입니다. 기본 실행은 측정을 거부하고 `--demo`를 명시하면 작은 CPU 산술 작업만 측정합니다. 모델·GPU·실제 학습을 실행하거나 과거 수치를 재현하지 않습니다. 환경명·사용자명·로컬 경로는 출력하지 않습니다.

템플릿은 준비 반복과 측정 반복을 나누고 중앙값·평균·p95·최솟값·최댓값을 JSON으로 반환합니다. 파일을 만들지 않습니다. p95는 nearest-rank 방식이며 작은 표본에서는 해석이 제한됩니다.

향후 실제 측정에 연결하려면 `measure`에 작업 함수와 완료 대기 함수를 전달하도록 별도 구현해야 합니다. 비동기 장치 작업에서는 호출 반환만이 아니라 작업 완료를 측정 경계로 삼아야 합니다. 장치별 연결은 현재 구현하지 않았습니다.

과거 loss 표와 이번 CPU 데모의 측정 결과는 서로 다른 자료입니다. 데모 숫자를 CV 성능 개선으로 제시하지 않습니다.

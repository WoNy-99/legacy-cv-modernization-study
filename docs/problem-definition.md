# 문제 정의

## 동기

기존 파이프라인의 실행 환경을 개선하고 결과 품질을 이해하려 했지만, 학습 설정·입력 특성·후처리 옵션·실행 환경이 함께 영향을 주어 문제를 분리하기 어려웠습니다. 최신 버전으로 바꾸거나 학습을 더 진행하는 것만으로 문제가 해결된다고 볼 수 없었습니다.

목표는 모델을 즉시 교체하는 것이 아니라, **원래 동작을 유지하면서 어떤 부분을 현대화할 수 있는지 확인하는 것**이었습니다.

## 질문

1. 증강 설정을 바꾼 뒤 loss와 관찰 품질은 어떻게 달라졌는가?
2. 사전 학습 상태의 재사용이 실제 적용되었음을 어떻게 확인할 것인가?
3. 품질 차이가 학습·분할·후처리·버전 중 어디에서 발생했는가?
4. 반복 시간과 샘플 처리량, 메모리 사용과 안정성을 어떻게 구분할 것인가?
5. 실행 환경을 변경하면서 보존해야 할 동작 기준은 무엇인가?

## 근거 유형

| 표시 | 의미 | 한계 |
|---|---|---|
| LOG | 사용자가 대화에 붙여넣은 실행·설정 출력 | 현재 재실행하거나 원본 파일을 검증한 것은 아님 |
| OBS | 사용자가 설명한 설정 변경·사용 경험 | 통제된 측정 또는 독립적인 시각 평가가 아님 |
| REPORT | AI 보조 작업 후 전달된 작업 보고 | 보고의 단계별 결과를 시스템 전체 성공으로 확대하지 않음 |
| PLAN | 과거 논의 또는 현재 정리한 설계 | 실제 구현·시험 완료를 의미하지 않음 |

2026년 4~9월의 관련 대화 중 확인 가능한 부분을 선별했습니다. 전수 복원은 아니며, 첨부 이미지를 재평가하거나 공개하지 않았습니다. AI가 제안한 수치·원인·기대 효과는 사용자 실행 로그와 구분했습니다.

## 범위와 비목표

- 과거 코드가 없으므로 이식 완료, 재현성 확보, 코드 품질이나 기여율을 소급 인증하지 않습니다.
- 원문 자료를 복제하지 않고 필요한 숫자와 오류 범주만 다시 서술합니다.
- 사전 학습의 적용 여부, 버전 회귀, 성능 개선 등은 해당 비교 근거가 부족하면 미확인으로 표시합니다.
- 설정 예시는 실행용 preset이 아닙니다. 측정 템플릿은 새 CPU 데모이며 과거 학습 결과를 재현하지 않습니다.
- 기존 문서에 없던 숫자를 추가한 이유는 관련 학습 대화를 추가 확인했기 때문입니다. 통제된 벤치마크가 새로 생긴 것은 아닙니다.

# 과거: 실험 및 시도 기록

아래 시기는 대화가 남아 있는 시점을 기준으로 합니다. 원래 작업의 정확한 시작·종료일이나 모든 반복 횟수를 의미하지 않습니다. 공개 설명에서는 응용별 명칭과 입력 세부사항을 생략했습니다.

## E01 · 입력 조건 확인 후 처리 중단

**시기:** 2026-04~05 · **근거:** 전달된 작업 보고 · **상태:** 단계별 부분 진행

- **하려던 일:** 입력을 처리하기 전에 정해 둔 형식 조건에 맞는지 확인하기.
- **남아 있는 기록:** 코덱·해상도·프레임률이 가정과 달라 다음 처리를 중단했다는 보고가 있습니다. 이후 조건에 맞는 입력에서는 추출과 메타데이터 틀 생성까지 진행했다는 별도 보고가 있습니다.
- **판단:** 입력 형식 확인과 후속 평가 승인은 별개의 단계입니다. 추출이 끝났더라도 라벨 검토가 남아 있으면 전체 완료가 아닙니다.
- **미확인:** 당시 산출물의 현재 재검증, 전체 평가 완료 여부.

## E02 · 자동 라벨링 후 유효 구간 없음

**시기:** 2026-05 · **근거:** 사용자 실행 결과 설명 · **상태:** 평가 준비에서 막힘

- **하려던 일:** 외부 가상환경의 Python 기반 자동 라벨링으로 수동 검토 부담을 줄이기.
- **남아 있는 기록:** 자동 처리 후 연속 구간 조건을 만족하는 결과가 없다는 출력이 전달되었습니다. 애매한 항목은 `needs_review` 또는 `unlabeled`로 남았다고 보고되었습니다.
- **판단:** 자동 처리가 실행된 것과 평가에 사용할 자료가 확보된 것은 다릅니다.
- **미확인:** 입력 특성, 추정 오차, 판정 조건 가운데 무엇이 주원인이었는지. 이후 제시된 AI 설명은 원인 확정의 증거로 사용하지 않았습니다.

## E03 · 백업 경로 준비 누락과 작업 상태 혼동

**시기:** 2026-05 · **근거:** 사용자 실행 출력 및 전달된 검증 보고 · **상태:** 오류 보고, 현재 복구 상태 재검증 불가

- **하려던 일:** 작업 자료를 보관하고 이전 작업 범위를 정리하기.
- **남아 있는 기록:** `rsync`에서 디렉터리를 만들지 못했다는 오류와 파일 I/O 오류가 발생했습니다. 삭제 명령을 반복한 뒤에는 `pathspec` 오류가 나타났습니다.
- **추가 보고:** 나중의 읽기 전용 검증 보고는 정리 작업이 이미 커밋되었으며, 남아 있는 다른 변경을 해당 작업과 함께 묶으면 안 된다고 설명했습니다.
- **판단:** 명령을 다시 실행하기 전에 실제 작업 트리·인덱스·커밋 상태를 확인해야 했습니다. 백업 명령을 실행한 사실만으로 백업 완료라고 판단해서도 안 됩니다.
- **미확인:** 당시 보관본의 무결성과 전체 파일 복구 가능성. 현재는 과거 코드가 남아 있지 않습니다.

## E04 · 하드웨어 변경 후 속도와 안정성 관찰

**시기:** 2026-06 · **근거:** 사용자 관찰 및 일부 반복 시간 출력 · **상태:** 원인 미확정

- **하려던 일:** CPU 교체 이후 실행 특성의 변화를 이해하기.
- **남아 있는 기록:** 같은 옵션을 사용했다고 설명하면서 반복 시간이 이전보다 짧아졌다고 보고했습니다. 동시에 이전에 없었던 시스템 문제가 생겼다고 설명하고 물리 메모리와 가상 메모리의 차이를 질문했습니다.
- **판단:** 처리 속도와 안정성을 따로 확인해야 합니다. CPU 공급 병목 완화나 메모리 설정 문제는 당시 논의된 설명이지, 여기서 검증한 결론이 아닙니다.
- **미확인:** 통제된 비교 조건, 메모리·프로세스 계측, 반복 측정, 장시간 안정성. 속도 향상률이나 소프트웨어 최적화 성과로 환산하지 않았습니다.

## E05 · 동작 보존을 전제로 한 최신 실행 환경 검토

**시기:** 2026-08~09 · **근거:** 설계 논의 · **상태:** 설계 방향 검토

- **하려던 일:** Python 및 프레임워크 실행 환경을 바꾸면서 기존 동작 기준을 유지하기.
- **남아 있는 기록:** 전처리·증강·난수·연산 정밀도·모델 구조를 무분별하게 바꾸지 않도록 작업 범위를 제한하고, 작업별 검증 조건을 갖춘 AI 보조 개발 방식을 요청했습니다.
- **판단:** 환경 현대화와 알고리즘 변경을 한 번에 수행하면 차이의 원인을 분리하기 어렵다는 문제의식을 정리했습니다.
- **미확인:** 실제 이식 코드, 수치 동등성 시험, 성능 시험. 제안된 PyTorch 전환이나 GPU 최적화를 구현 완료 항목으로 취급하지 않습니다.

## 남은 결론

여러 단계에서 실행과 검토를 시도했지만, 전체 파이프라인의 현대화 성공을 입증할 자료는 없습니다. 부분 진행 보고는 남아 있으나, 현재 그 코드를 실행해 재현할 수는 없습니다.

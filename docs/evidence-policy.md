# 기록의 근거와 한계

## 작성 방법

2026년 4~9월의 관련 대화 중 확인 가능한 부분을 선별해 기술적 문제만 다시 서술했습니다. 모든 과거 작업을 복원한 전수 기록은 아닙니다. 원문 대화, 과거 저장소, 실행 파일을 이 저장소에 복사하지 않았습니다. 이 저장소의 커밋 날짜는 문서 작성 날짜이며 과거 개발 이력이 아닙니다.

| 근거 유형 | 이 문서에서 의미하는 것 | 의미하지 않는 것 |
|---|---|---|
| 사용자 실행 출력 | 대화에 명령 결과나 오류 출력이 남아 있음 | 현재 재실행·검증 완료 |
| 사용자 관찰 | 본인이 사용 경험과 관찰을 설명함 | 통제된 실험 결과 |
| 전달된 작업 보고 | AI 보조 작업 후의 보고가 대화에 붙여넣어짐 | 독립 검증된 구현·시험 성적 |
| 설계 논의 | 개선 방향과 제약을 요청하거나 검토함 | 제안된 작업이 실행됨 |
| 현재 설계 | 이번 문서화에서 정리한 다음 단계 | 과거부터 구현되어 있던 기능 |

## 과장 방지 기준

- 오류 출력이 있으면 해당 오류가 보고되었다고 기록합니다. 다른 환경에서도 재현된다고 단정하지 않습니다.
- 작업 보고의 PASS는 보고가 다룬 제한된 단계에만 적용합니다. 시스템 전체 성공으로 확대하지 않습니다.
- AI의 원인 설명은 실행 증거가 없으면 가설로 남깁니다. 예상 속도·기대 효과를 실측치로 옮기지 않습니다.
- 원본 코드가 없으므로 코드 품질, 테스트 통과, 구현 기여율, 재현성을 소급 인증하지 않습니다.
- 다른 작업 시점의 보고를 한 번의 연속된 성공 사례로 합치지 않습니다.
- 모든 원인을 확정하지 못한 상태를 그대로 남깁니다.

## 공개 범위

공개 자료는 새로 작성한 Markdown 문서뿐입니다. 입력 자료, 실행 바이너리, 학습 산출물, 원문 대화 첨부물, 로컬 환경 설정은 포함하지 않습니다. 과거 코드를 새 코드로 복원했다고 주장하지 않습니다.

따라서 이 사례는 **문제 인식과 설계 판단을 설명하는 자료**이며, 실행 가능한 구현 포트폴리오를 대체하지 않습니다.

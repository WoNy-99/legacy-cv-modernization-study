# 기존 파이프라인 분석

**범위: 사용자 설명과 실행 기록을 일반화한 구조. 소스코드 전체를 현재 감사한 결과가 아닙니다.**

![일반화한 처리 단계](../diagrams/pipeline.svg)

| 단계 | 기록에 나타난 작업 | 분석할 경계 |
|---|---|---|
| 입력 준비 | 입력 형식 검사와 프레임 추출 | 크기·시간 단위·조건 불일치 |
| 전처리·분할 | 전처리, 자동 분할, 추가 학습 및 적용 | 분할 결과와 최종 품질의 관계 |
| 학습 | 설정 변경, 사전 학습 상태 재사용 시도, loss 확인 | 설정 변경 시점과 비교 조건 |
| 내보내기 | 학습 후 별도 실행 단계로 이동 | 새 산출물이 실제 로드되었는지 |
| 추론·후처리 | 버전 및 preset 변경, 복수 보정 기능 사용 | 경계·색·형태와 메모리 영향 |
| 결과 검토 | 프리뷰를 보며 문제 보고 | 주관적 관찰과 정량 평가의 구분 |

## 확인된 기술 주제

- **학습 설정:** 해상도 256·284·320 사용에 대한 설명, batch 8→16 변경 설명, geometric warp 전환, `lr_dropout` 사용 습관. 모든 조합을 비교 시험한 것은 아닙니다.
- **모델 계열:** encoder–decoder 학습 파이프라인으로 일반화했습니다. 보존된 구현을 제시하는 구조도가 아닙니다.
- **최적화 설정:** 일부 설정 출력에서 AdaBelief 사용이 보입니다. 전체 과거 실행에 동일하게 적용되었다고 가정하지 않습니다.
- **실행 환경:** Python, CUDA, PyTorch, ONNX Runtime GPU 및 Gradio 계열 의존성의 설치·기동 문제.
- **현대화 논의:** TensorFlow 기반 기존 동작을 PyTorch 환경으로 옮기는 방향. 실제 전환 성공은 미확인입니다.

## 분할 문제를 별도 단계로 보는 이유

자동 분할이 어떤 상황에서는 경계를 잘 제외하고 다른 상황에서는 불필요한 영역까지 포함한다는 사용자 보고가 있었습니다. 사용자는 수동 라벨과 자동 생성 결과의 학습 반영 방식에 대해 AI 설명의 재확인을 요구했습니다.

이 기록은 분할 동작을 점검할 필요성을 보여주지만, 특정 내부 구현이나 단일 원인을 이 저장소에서 검증했다는 의미는 아닙니다. 당시 데이터·가중치·전처리·후처리 설정을 고정한 비교가 없으므로 기여도를 분리할 수 없습니다.

## 호환성 검토 항목

입력과 전처리의 의미, 보간과 난수 처리, 연산 정밀도, 텐서 배치, 학습 설정 해석, 저장 상태 로딩, 내보내기와 후처리의 연결을 별도로 확인하는 설계가 필요합니다. 위 항목은 검사 계획이지 통과한 시험 목록이 아닙니다.
